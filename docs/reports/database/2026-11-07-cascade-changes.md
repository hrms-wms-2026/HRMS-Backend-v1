# Foreign key changes for SQL Server

**Date:** 2026-11-07

SQL Server rejects self-referencing cascades, multiple cascade paths, and foreign keys whose column length differs from the key they point to. PostgreSQL allowed all of these. Of 65 cascade or set-null rules, 3 had to change.

## Delete behaviour changed to NoAction

| Foreign key | Was | Code that relied on it |
|---|---|---|
| `fk_personal_calendar_events_recurrence_parent_id` | Cascade | None found. `CalendarEvent` is soft-deleted, so `Remove` never ran the cascade. `RemoveHolidayEventsForYearAsync` hard-deletes holiday rows only, which have no recurrence children. |
| `fk_refresh_tokens_refresh_tokens_replaced_by_id` | Set null | None. Nothing deletes refresh tokens. |
| `fk_monitoring_evidence_assets_agent_commands_agent_command_id` | Set null | None. Nothing deletes agent commands. |

If code later hard-deletes these rows, it must clear or delete the dependents first.

## Column lengths widened to match the referenced key

| Column | Was | Now |
|---|---|---|
| `module_integration_links.module_key` | 80 | 100 |
| `payment_gateway_configs.provider` | 30 | 50 |
| `platform_oauth_apps.provider` | 30 | 50 |
| `integration_catalog.onevo_app_provider` | 30 | 50 |

`ForeignKeyColumnsMatchTheirPrincipalTypes` guards this from now on.

## Index key limit

`monitoring_face_scans.storage_key` went from 1000 to 850 characters, the most a SQL Server index key allows. Keys are generated by the app and are far shorter.
