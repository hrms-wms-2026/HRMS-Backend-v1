# Backend module map

One row per feature area under `src/ONEVO.Application/Features/` (verified 2026-10-28). Each area follows the same layer layout (architecture document §2.1): use cases in `Application/Features/<Area>`, entities in `Domain/Features/<Area>`, EF repositories and adapters in `Infrastructure/Persistence/Repositories/<Area>` and `Infrastructure/Services|ExternalServices`, controllers in `Api/Controllers/{Tenant|Admin}/<Area>`.

"Docs" names where to look: plans and designs are under `docs/superpowers/plans|specs/{next,finished}/` (search by the keyword), reports under `docs/reports/<area>/`.

| Area | What it does | Sub-features | Docs |
|---|---|---|---|
| **Auth** | Login (base-domain, Google), workspace selection, session exchange, MFA, password reset, invitations, legal acceptance, roles and permissions, user accounts and session revoke, switching the active company | ActiveCompany, Invite, Legal, Login, Permission, Roles, UserAccounts | `superpowers/workflow/authentication.md` (verified flow, cookies, CSRF); plans/specs `auth`, `login`, `legal`, `sso`, `workspace-shortcut` |
| **Calendar** | Company calendar: events, recurrence, time zones, RSVP and conflicts, external guests, Google/Microsoft sync, Teams/Zoom meetings, meeting exceptions | (single feature folder) | plans/specs `calendar-*`, `teams-zoom-meeting-integration`; `postman-request/` |
| **Conversations** | One-to-one and group chats between employees, messages, revisions, mutes | (single feature folder) | `postman-request/Conversations/`; rich-text rule in architecture §4.2.2 |
| **CoreHr** | Employees, onboarding drafts and finalization, bulk onboarding, offboarding, position assignment, reporting-manager resolution, employee authority (who can see whom) | BulkOnboarding, Employee, EmployeeAuthority, EmployeeHierarchyClosure, Offboarding, Onboarding, OnboardingDraft, OnboardingWorkModes, PositionAssignment | `reports/onboarding/`, `reports/employee/`; plans/specs `employee-*`, `onboarding`, `offboarding`, `reporting-manager` |
| **Dashboard** | Customizable dashboards: layouts, widget registry and data providers (My Work, My Team), team widgets | Layout, Team | plan/spec `customizable-dashboard`, `team-attendance-widget`; `reports/dashboard/` |
| **DevPlatform** | Platform administration: tenants and provisioning, subscriptions and billing, module and app catalog, configuration templates, compliance (legal documents), platform users and access, system config (OAuth apps, payment gateways, tray releases, service keys) | AppCatalog, Billing, Compliance, ConfigurationTemplates, ModuleCatalog, PlatformAccess, Provisioning, Subscription, SystemConfig, Tenancy | plans `admin-*`, `invite-platform-manager`, `tray-installer-release-management`; most UI docs live in the platform-admin repo |
| **Inbox** | Unified inbox of approvals and cases across modules, chats on items, escalation, 30-minute revert of decisions | Chats, Escalation, Revert, ... | `postman-request/Inbox/`; frontend `reports/work-management/user-journey/INBOX_USER_JOURNEY.md` |
| **InfrastructureModule** | Country defaults and the platform user record | CountryDefaults, User | — |
| **Leave** | Leave types, policies (versioned, assigned), entitlements and balances with audit, requests, approval and cancellation, team calendar | Approval, Balance, BalanceAudit, Calendar, Cancellation, Entitlement, Policy, Request, Type | plans `next/2026-08-21-leave-management/`, spec `leave-approval-forward-and-history` |
| **Monitoring** | Tray-agent monitoring: activation and device state, check-in with face match, activity and app usage, screenshots, work sessions and locations, meetings, exceptions, daily reports, policies and settings, client logs | ActivityMonitoring, AppUsage, Biometrics, CheckIn, ClientLogs, DailyReport, DeviceState, Exceptions, Meetings, Notifications, PermissionConsent, Policy, Reports, Screenshots, Settings, TrayActivation, WorkLocation, WorkSessions | `reports/monitoring/`; plans `face-match-verification`, `inactivity-screenshot-daily-report`, `meeting-detection`, `work-pattern-productivity-model`. Thin for its size (see gap audit). |
| **OrgStructure** | Legal entities (general settings, logo, work time), departments, positions and coverage, position template packs | Department, LegalEntity, Position, PositionTemplatePacks | `reports/legal-entity/`, `reports/org-structure/` |
| **SharedPlatform** | Notifications (in-app, email, durable delivery), tenant integrations, inbound webhooks | Notifications, TenantIntegrations, Webhooks | `docs/notifications/`, `reports/notifications/` |
| **Storage** | File upload and download (R2), upload purposes and signature checks, quotas, entity assets | EntityAssets, File, Quota | little; see gap audit |
| **TimeAttendance** | Clock-in/out, breaks, attendance records and history, corrections, work-area change requests, alerts, team attendance | Alerts, Team, Inbox, ... | `reports/attendance/`, `reports/time-tracking/`, `reports/work-area/` |
| **WorkManagement** | Projects, modules (objectives) and hierarchy, members and invitations, tasks, sprints, approvals and reverts, labels, versions, release calendar, work graphs, employee overview, leadership views, monitoring and notifications | Approvals, Hierarchy, Objectives, Projects, ProjectMembers, ProjectInvitations, Sprints, Tasks, EmployeeOverview, EmployeeWorkGraph, ProjectWorkGraph, Leadership, Labels, Versions, ReleaseCalendar, Monitoring, Notifications, Inbox, Common | most plans/specs (`wm-*`, `task-*`, `sprint-*`, `work-management-*`); `postman-request/Work Management/` |

Cross-cutting pieces outside `Features/`: MediatR pipeline behaviors (`Application/Common/Behaviors`), shared helpers such as `RichTextRules` (`Application/Common/Helpers`), tenant isolation (`Infrastructure/Persistence` interceptors + RLS migrations), and the background jobs listed in the architecture document §1.2.
